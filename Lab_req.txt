3. Prepare the new user-testing sessions
Use the same two tasks you defined in Lab 7.
Task 1 — Strategy Creation and Backtesting
Ask the participant to create a strategy, configure its parameters and historical period, run the backtest, inspect the performance, and explain what happened.
Record:
- Whether the task was completed independently.
- Total time.
- Errors or incorrect actions.
- Whether the participant correctly explains the backtest results.
Task 2 — Exploration
Ask the participant to change one or more parameters, run a variation, compare it with the original, and explain what changed.
Record:
- Whether the participant successfully creates and runs a variation.
- Total time.
- Whether they can identify the configuration used for each run.
- Whether they can correctly explain the difference in results.
Use neutral prompts such as “What are you looking for?” and “What do you expect to happen?” Avoid telling participants where to click.

Use the same five questions and the same 1–5 scale for the new participants to make the comparison meaningful.
You can calculate the change as:
\[
\text{Score Change}=\text{New Average}-\text{Lab 7 Average}
\]

For example, if Q5 rises from 3.2 to 4.0, the improvement is \(+0.8\) points. That is only an illustration; use your actual new results.
Also compare task completion, completion time, and errors. Since Lab 7 used different participants, describe this as a before-and-after comparison between two user groups, not proof that the interface alone caused every difference.
6. Apply all three evaluation methods
Your slides distinguish three methods. Make sure all three are represented in your work.
A. Usability Inspection
Expert inspection
Recheck the Lab 7 heuristic findings against the current build. Use Nielsen's heuristics, assign severity from 0–4, and record evidence for each unresolved issue. A cognitive walkthrough can additionally assess whether the next action is discoverable for a first-time user.

B. User-Based Evaluation
Five or more new users
Conduct both tasks, collect times and errors, administer the questionnaire, and compare the results with Lab 7. This is your main source of evidence about actual user behaviour.

C. Accessibility Evaluation
Tools and manual checks
Check contrast, text size, keyboard navigation, and accessible labels. Tools such as Lighthouse, WAVE, or a contrast checker can help, but manually test keyboard operation and actual rendered content as well.
